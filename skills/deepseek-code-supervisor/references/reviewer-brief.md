# 二轮检测 · 子智能体版

自检可以做，但不能当终检。写代码的和出最终结论的，必须是两个上下文。

这份简报用在两处：

- **L2 交付前终检**：**只对改了业务逻辑代码的大改动**，且自检报 0 处、**用户弹窗确认之后**才起一次。
- **L3 换角度**：修完重自检一轮仍有问题才起新的，换查法。

**纯运维 / 配置任务（域名、DNS、重定向、部署、环境变量、证书、缓存、平台控制台设置）不起 L2**，
走轻量三项：跳转链 / 资源终态 / 功能抽样，只做 1 条反例。见 `references/scenarios.md` 七。
**纯文档 / 提示词改动不起 L2，也不弹窗**，按文本口径自检 + 两个取证交付。

小改动跳过 L2；大改动若用户在弹窗里选「跳过」或没回复，**同样不起**，报告写明"未起终检（用户跳过 / 未获确认）"。
用户明确说「终检」「起子智能体」= 已确认，不用再弹一次。
未起 L2 时主智能体的六项和两个取证一项不省。

## 怎么调用

**派单之前先弹窗确认**（`ask_user_question`），文案固定：
「本轮判定为大改动，是否进行独立终检？终检预估耗时较长（实测 3–8 分钟、主智能体静默），
但能提高代码质量、避免交付带 bug 的产物。等不等由你定。」
给「进行终检 (推荐)」「跳过，只自检交付」；用户没确认就不派这一单。用户已明确说「终检」= 已确认。
纯聊天环境没有弹窗工具 → 降级成对话里问同一句（含耗时与收益），等回复；没回复按跳过处理。
**耗时与收益两句不许省**，只问「要不要」是让用户盲选。

**默认前台，异步派单、主智能体静默**；主智能体仍可做别的事，但不承诺定期播报。用户明确要求后台才切。

**派单前先给用户一行**，写全四项：

`[L2 终检] 已派出 → 验 <文件A/B> → 预算 10 分钟 / 12 turns → 主智能体静默 → 回来给结论`

不许只写"正在验收"。

**静默窗口的边界**：等待期间主智能体不主动输出，但系统级完成通知（后台任务、队友通知）可能插进来。
看到通知 ≠ 终检结论回来；后台结论一律标注「这是上一轮派出的终检结果」，不许混作当前轮。

用 `subagent` 起一个子智能体：

- `description`：`二轮检测`
- `prompt`：下面提示词段 + 本轮的具体信息（改动清单、文件路径、产物路径、运行方式）
- 预算写进 prompt：**12 turns，不许上调**；10 分钟；同类外部请求 ≤3、HTTP ≤8、反例 ≤1

**输入预算**：只给改动文件及其直接调用方、产物、一条验证命令。
**不要传**：设计思路、为什么这么改、遇到的问题、上一轮结论。传了它就会替你想理由。
**禁止它**：遍历全项目、翻 `references/`、装依赖、跑全量测试套件 —— 这些都是无效耗时。
**单轮请求预算**：同类外部请求 ≤3 次、HTTP 总请求 ≤8、反例 ≤1 条。

**要求它**：只出结论，不改代码，**固定骨架短结论**。细致报告由主智能体写，不让它写长篇。

默认前台。异步派单后按约定不朝用户输出，派单那一行是用户唯一能看到的字，必须写全。

## 给子智能体的提示词（整段复制）

```
你是这一轮改动的独立验收人。你没有参与写这些代码，也不知道作者为什么这么设计。
不要猜测作者的意图，只看代码的行为和产物。作者的解释不算证据。

==================================================
项目与范围
==================================================
项目：<项目名 / 技术栈 / 怎么启动>
本轮改动：
- <文件1>：<改了什么>
- <文件2>：<改了什么>
产物：<产物路径 / 页面地址 / 接口地址 / 数据表>
怎么验：<一条能跑的命令>

==================================================
执行边界（照这个顺序，别自己加步骤）
==================================================
1. 先做完两个取证 A、B。这两件最快出结论。
2. 再按六项顺序查。只查上面列出的改动文件及其直接调用方，不遍历全项目。
3. 不读 references/ 或项目里的规范文档 —— 判据已经写在下面。
4. 不装依赖、不跑全量测试套件、不重构、不改代码。
5. 六项逐条查完再出结论。找到 P0 也继续查完，不许中途收工 —— 早停会让六项记录和 L3 计数同时失效。
6. 验证只跑上面「怎么验」那一条命令，贴输出。
7. 单轮预算：同类外部请求 ≤3 次、HTTP 总请求 ≤8、反例 ≤1 条、12 turns。到任一上限停止扩展验证。
8. 到预算上限：已查完的项写全，其余逐项标「未查完（达到预算）」+ 原因，结论写「有条件通过」或「未查完」，
   不许写"通过"。预算不是提前收工的理由，是不谎报的理由。
9. 外部平台限制（403 / 配额 / 限流 / 依赖服务超时 / 控制台拦截）→ 记为「未决项」：
   不重试、不计入 L3 触发计数、不升级轮次。换凭证或换路径最多试一次，仍失败即定案，写出解除条件。
10. 最终报告带一行执行摘要：查了几项、发了几次外部请求、时间花在哪。

==================================================
你要做的六项检查
==================================================
1. 代码逻辑错误
   走一遍数据流：输入 → 分支 → 输出。把所有分支列出来，标出没有处理的。

2. 死代码 / 无用代码
   每个新增的函数、变量、参数、导入，grep 引用数。0 引用就是死代码。

3. 不影响原有功能
   每个改动点找调用方，核对签名和语义。改签名没改调用方 = 直接失效。

4. 恶性误用 bug
   逐项回答"有 / 无 + 依据"：
   空值（null/undefined/""/0/空数组）、越界、并发与重复提交、资源未释放、
   异常路径、外部调用超时。

5. 功能失效
   跑上面「怎么验」那条命令 + 一次真实输入，贴输出。跑不了就明说，不要写"应该没问题"。

6. 结构与内容错误
   分层是否合理、函数边界是否清楚、命名和实际行为是否一致、
   注释是否过期、配置和代码是否同步、有没有同一规则存了两份。

==================================================
两个必须做的取证动作（不做就等于没查）
==================================================
A. 打开产物看一遍。不看代码，直接看改完的东西：打开文件、截图、curl、select 数行。
   产物的哪一处变了，变对了没有。

B. 把期望值改坏一个字节，测试必须红，然后恢复。
   还绿就说明这条测试从来没验过东西。

==================================================
输出格式（固定）
==================================================
**输出上限：固定骨架短结论。** 不贴大段原始输出、不写长篇分析、不做扩展探测报告。
细致报告由主智能体写给用户，不是你的活 —— 实测要求「细致报告」会把一轮终检从 3 分 16 秒拖到 7 分 57 秒。

## 二轮检测结论：通过 / 有条件通过 / 不通过

判定：有任何 P0 = 不通过；只有 P1 = 有条件通过；只有 P2 或没有 = 通过。
任一项没查完，结论不得写"通过"，须标"未查完 + 原因"（含预算耗尽）。
预算截断轮的「未查完」不计入 P0/P1 处数。

==================================================
你的行为约束
```

## 主智能体拿到结论之后

1. **原样呈现**，不许改写、不许过滤、不许替它软化。
2. 有 P0 → 直接判不通过。修完重做 L2（还是 L2，不是 L3）。
3. 报出 2 处以上 P0/P1，或 L2 已经做了两轮还不干净 → **先修完再自检一轮**，仍有问题才起新的进 L3。
   **外部平台限制记未决项，不计入这个计数、不升级轮次；预算截断轮的未查完也不计入。**
   **轮次计数只有一个轴：L3 轮数（最多两轮）。** L2 做几轮不另算，修完重自检几轮也不另算 ——
   不要自己发明第三个数。
   同一个问题最多修 **2 轮**，第 3 轮开始前必停，把残留问题写进报告（这是防无限返工的硬刹车）。
4. **每次都是新的子智能体。** 同一个连续看两轮，会开始维护自己上一轮的判断。
5. 复查时给它**新的改动清单**，不要给它上一轮的结论 —— 否则它会被你的结论带偏。
6. 用了后台模式：收到完成通知后先把结论原样贴出，再补一句"这是上一轮派出的终检结果"。
   别让用户以为那是刚跑出来的。
7. **细致报告由主智能体写给用户**：把短结论当输入，逐节给证据（改了什么 / 验了什么 /
   没验什么 / 未决项 / 剩余风险）。别把短结论原样当最终报告，也别为凑细致再起一轮或让它补长报告。

## 起不了子智能体怎么办

两种情况：环境没有子智能体；或者你在纯 DeepSeek 会话里，只有一份聊天框。

降级方案，按优先级：

1. **新开一个会话**：只贴改动文件 + 产物 + 六项清单，不贴你的思路。效果接近。
2. **角色切换**：在同一个会话里，明确写"下面这段不是你写的，你是外部验收人，不要替它辩护"，
   并且**只贴 diff 和产物**，把之前的讨论放在一边。效果打折，聊胜于无。
3. **只做两个取证动作**：打开产物数一遍、把期望值改坏看测试红不红。
   这两件事不依赖上下文，是最后的底线。

**底线不能破**：宁可只做两件取证动作，也不要写"已全面检查"。
