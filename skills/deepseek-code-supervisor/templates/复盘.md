# 复盘

> 追加写到项目 `.workbuddy/复盘.md`。不覆盖。下次开工先读。

```markdown
## <日期> · <项目/模块>

**结论**：通过 / 有条件通过 / 不通过

### 1. 我以为对、实际错的那一处
- 位置：<文件:行号> 或 <产物:第几段/第几项>
- 我以为：<当时的判断>
- 实际：<真实情况>
- 怎么发现的：<命令 / 对照 / 用户指出>

### 2. 哪一项本来能拦住
- 项：<1 产物 / 2 可证伪 / 3 静默 / 4 接口 / 5 一致 / 6 边界 / 7 泛化>
- 当时为什么没走：<不知道有这一项 / 图快 / 以为已经验过 / 环境不允许>

### 3. 补一条规则
> <一句话，祈使句，能直接加进开工令>

### 附：这轮没验的
- <项> —— <原因>
```

## 判定：这份复盘有效吗

| 情况 | 判定 |
|---|---|
| 第 1 条写不出具体位置（只有"整体顺利"） | 无效，回去查 |
| 第 1 条写成"我完成了 A、B、C" | 无效，那是流水账不是复盘 |
| 第 2 条写"六项都查了" | 无效，查了还出错，说明查法不对 |
| 第 3 条写成"以后要更仔细" | 无效，不可执行 |
| 附录空着 | 无效，没验的必须列 |

## 三条常见的假复盘

1. **归因给外部**："模型能力不行""工具不支持""环境有问题"。
   先证明这三条，证明不了就回来找自己的判断错误。
2. **归因给态度**："下次注意""更仔细一点"。这类结论改不了任何行为。
3. **归因给范围**："需求太模糊"。需求模糊的时候你问了吗？没问就是你的问题。
