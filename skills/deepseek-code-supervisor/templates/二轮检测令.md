# 二轮检测令

> 单次触发用。已经贴过开工令的，直接用它里面第七段；没贴过开工令的，贴这一份。
> 改了业务逻辑代码的大改动才另起一个没参与写作的上下文；小改动、纯运维/配置不用这一份。
> 派单前先弹窗确认「是否进行独立终检」，用户点了确认才起；用户已明确说「终检」视为已确认。
> 弹窗必须写清：终检预估耗时较长（实测 3–8 分钟、主智能体静默），但能提高代码质量、避免交付带 bug 的产物。
> 只给它下面这段话和改动清单。
> 纯运维 / 配置（域名、DNS、重定向、部署、证书、缓存）不用这一份，走轻量三项（跳转链 / 资源终态 / 功能抽样）。
> 派出去之前先回我一行：`[L2 终检] 已派出 → 验 <文件A/B> → 预算 10 分钟 / 12 turns → 主智能体静默 → 回来给结论`
> 派出后主智能体不主动输出。不许只写"正在验收"，不许承诺定期播报。
> **验收上下文只回 固定骨架短结论；细致报告由你写给我，别让它写长篇。**
派出后主智能体不主动输出；期间可能收到系统通知，看到通知不代表终检结论回来，
后台结论要标注「这是上一轮派出的终检结果」。

```
请你对本轮改动的代码及产物进行二轮分析，确保没有代码逻辑错误，去除死代码和无用代码，
确保不影响原有功能，没有恶性使用 bug，不得产生功能失效的问题。

先做两个取证，再逐项查完六项，最后按要求输出。找到 P0 也继续查完，不许中途收工。

单轮预算：12 turns / 10 分钟；同类外部请求 ≤3 次、HTTP 总请求 ≤8、反例 ≤1 条。
到上限停止扩展验证，已查完的写全，其余标「未查完（达到预算）」+ 原因，结论不许写"通过"。
外部平台限制（403 / 配额 / 限流 / 控制台拦截）→ 列为未决项，不重试、不升级轮次，写解除条件。

【范围】
改动的文件：
- <文件1>：<改了什么>
- <文件2>：<改了什么>
不许顺手动的地方：<列出>

【六项，每项写「查了什么 / 看了哪里 / 发现几处」】
1. 逻辑错误 —— 数据流 输入→分支→输出，列出全部分支，标出没处理的
2. 死代码 —— 新增函数、变量、参数、导入 grep 引用数，0 引用就删
3. 原有功能 —— 每个改动点找调用方，核对签名与语义
4. 误用 bug —— 空值、越界、并发、资源、异常路径、重复提交、超时，逐项"有/无 + 依据"
5. 功能失效 —— 跑原有测试 + 新增测试 + 一次真实输入，贴命令和输出
6. 结构内容 —— 分层、函数边界、命名与实现、注释、配置

【两个取证动作，不做等于没查】
A. 打开产物看一遍：不看代码，直接看改完的东西（文件 / 截图 / curl / select）。
   产物哪一处变了，变对了没有。
B. 把期望值改坏一个字节，测试必须红，然后恢复。报红就是有效，还绿就是这条测试没验过东西。

【输出】
只回 固定骨架短结论，不贴大段原始输出、不写长篇分析。
细致报告由主智能体写给用户，别在这里展开 —— 实测要求「细致报告」会把一轮终检从 3 分 16 秒拖到 7 分 57 秒。
【交付前】能跑机械门禁就跑一次，不通过不许报通过；纯聊天跑不了脚本 → 按上面六项逐条自检，
报告写「门禁未运行（纯聊天环境）」。
```

## 三轮往后

先把第一轮报出的问题修完，再自检一轮；仍有问题才换查法。外部平台限制记未决项，不计入这个计数、不升级轮次。
换入口，不是换遍数：

1. 从产物反推：先看产物哪里不对，再回去找哪段代码造成的。
2. 从调用方反推：假设第一次用这个函数，会怎么用错。
3. 从失败路径反推：每个 else / catch / 空值，逐条问"这里会发生什么"。
4. 从删除反推：把新代码整段注释掉，看哪些测试会红，不红就是没测到。

换过两轮还是 0 处，停。两轮后还有 P0，把没解决的列出来问我要不要继续，
别自己算"差不多够了"就收。
