# 施工单

> 改动动手之前填。不超过 12 行。用户确认了再开工。

```markdown
## 施工单 · <日期>

**改**
- <文件1> → <函数/行区间>：<改什么>
- <文件2> → <函数/行区间>：<改什么>

**不改**
- <用户明确说别动的东西，落成具体文件/模块>
- <这次不碰的相关模块，写明"本次不碰">

**验收**
- 命令：`<一条能跑的命令>`
- 期望：<看到什么算过；数字写具体>
- 反证：<把什么改坏，应该报什么错>

**风险**
- <最可能坏的地方>：<为什么>

**回滚**
- <备份路径 / git 提交号 / md5 文件>
```

## 填法

| 字段 | 要求 | 不合格的写法 |
|---|---|---|
| 改 | 文件 + 函数/行区间 + 一句改什么 | "优化一下逻辑" |
| 不改 | 具体文件清单 | "其他都不动" |
| 验收 | 命令 + 期望结果（含数字） | "看效果" |
| 反证 | 改坏哪里、应该报什么 | 空着 |
| 风险 | 最可能坏的一处 | "应该没问题" |
| 回滚 | 具体路径或提交号 | "git 里都有" |

## 三条规矩

1. **"不改"必须显式列。** 用户说"其他别动"，就把"其他"落到文件清单上。
2. **超过 2 个文件就拆批。** 一批一验，别全改完再验。2 个文件同时是大改动的判据，两处口径一致。
3. **验收必须能自动跑。** 只能肉眼看的部分，单独标出来，写进"没验什么"。
