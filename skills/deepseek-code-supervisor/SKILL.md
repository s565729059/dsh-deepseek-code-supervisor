# 二轮检测

写完不算完，验完才算完。一次性脚本跑通就扔的，别走这套。

## 〇、开工前

1. 把需求压成 3–5 条可验收判据，写下来；测不了的当场说清。
2. 修 bug 先复现：一条能红的命令或测试，贴输出。修完同一条必须绿。
3. 改动超过 2 个文件先拆分批，改前留回滚点（commit / 副本 / md5）。

## 一、先分类

| 类型 | 查什么 | 独立终检 |
|---|---|---|
| 代码（改了函数、分支、接口、数据结构） | 六项 + 两个取证 | 大改动 + 用户确认 |
| 运维 / 配置（域名、DNS、重定向、部署、环境变量、证书、缓存、控制台） | 轻量三项 | 不起 |
| 混合 | 代码六项 + 配置三项 | 看代码部分 |
| 文档 / 提示词（只改 .md / .json 文本） | 文本口径自检 + 两个取证 | 不起 |

轻量三项：跳转链（`curl -I` 逐跳贴 Location 和终态码）、资源终态（before → after）、功能抽样（2–3 条真实请求贴状态码和关键响应行）。运维类只做 1 条反例，不跑全量回归。

## 二、大小判定（只对代码改动）

大改动命中任一：≥2 个文件 / 净增删 >30 行 / 动函数签名或数据结构 / 写删业务数据 / 权限密钥支付回调 / 并发异步定时 / 加依赖改配置 / 修线上 bug / 只能肉眼看。

小改动全满足：1 个文件 / ≤30 行 / 不动签名字段 / 不碰数据权限并发 / 一条命令能验。拿不准按大改动。

## 三、自检六项

1. 逻辑错误：走数据流 输入→分支→输出，列全部分支，标出没处理的。
   补丁 / 迁移 / 幂等类改动额外查方向（判据是「新文已在」还是「旧文不在」）。
2. 死代码：每个新增函数、变量、参数、导入 grep 引用数，0 引用删掉。
   删功能类改动额外查爆炸半径（关键词出现次数、调用点全集、被谁 import）。
3. 原有功能：每个改动点找调用方，核对签名和语义。
4. 误用 bug：空值、越界、并发、资源泄漏、异常路径、重复提交、超时，逐项「有/无 + 依据」。
5. 功能失效：跑原有测试 + 新增测试 + 一次真实输入，贴输出。
6. 结构内容：分层、函数边界、命名与实现、注释是否过期、配置是否同步。
   拿大小做预算表时用字节数并标单位（`len(str)` 是字符数，中文 1 字 3 字节）。

每项写「查了什么、看了哪里、发现几处」。只写「已检查」等于没查。自检看 diff，不看记忆。
方向判断、爆炸半径、落盘复检、单位口径的具体判据见 `references/checks.md` 取证 8。

## 四、两个取证（不做等于没查）

A. 打开产物数一遍：不看代码，看文件、截图、curl、select。产物没变就是没生效。
   落盘类改动写完要重读一遍。
B. 把期望值改坏一个字节，测试必须红，然后恢复。还绿说明这条测试没验过任何东西。

**没有测试框架、没有可跑入口时**，B 换成等价动作，仍要贴证据：

- 纯库 / 无入口：写一个最小调用样例，改坏它的期望输出，样例必须报错。
- 纯脚本：把实现里的关键常量改成一个明显错的值，跑真实输入，输出必须随之错。
- 实在做不了 B：A 不能省，B 写「未验 + 为什么这个项目做不了」，不许静默跳过。

## 五、独立终检（L2）

前置：大改动 + 自检 0 处 + 用户确认。

先问用户，把代价和收益说清：预估耗时较长、主智能体静默，但能提高代码质量、避免交付带 bug 的产物。两个选项：「进行终检」「跳过，只自检交付」。用户说「终检」「起子智能体」= 已确认，不再问；跳过或没回复 → 不起，报告写明。

派单用 `subagent`：

- `description`：二轮检测
- `prompt`：`references/reviewer-brief.md` 的提示词段 + 改动清单、文件路径、产物、一条验证命令
- 预算写进 prompt：10 分钟 / 12 turns，同类外部请求 ≤3、HTTP ≤8、反例 ≤1
- 只给改动文件及其直接调用方，不给设计思路和上一轮结论
- 子智能体只回固定骨架短结论；细致报告由主智能体写给用户

起不了子智能体时降级：新会话只贴 diff → 同会话切角色只贴 diff → 至少做两个取证。

可选：终检换一个模型（先 `list_subagent_models` 看可用项），和写代码的模型错开，减少同源盲区。

## 六、机械门禁（能跑就跑）

能跑就跑，跑不了写「未跑」，不许跳过。

- 仓库自带的 lint / type-check / test 命令跑一遍，失败按 P0 处理，贴原样输出。
- `scripts/scan_risks.py <改动文件>`，出现 BLOCK 必须清零。
  退出码：`0` 无 BLOCK / `1` 有 BLOCK / `2` 路径或规则表故障 / `3` 一个可扫文件都没有 / `4` 有文件读不了。
  **只有 `0` 算通过**。`3` = 这个项目不在脚本支持范围内（它只认 py/js/ts/sh 四类语言），
  `4` = 覆盖不完整（非 UTF-8、二进制）。两种都要在报告里写明「该门禁未覆盖」。
  它**不查死代码** —— 第 2 项必须人工 grep。
- 改过规则表或脚本本身，先跑 `python scripts/test_scan_risks.py`（它检查检查器自己，22 项）。

发布类改动另加三查，见 `references/scenarios.md` 六（部署与发布）。

## 七、换角度（L3）

进 L3 之前先修完 + 重自检一轮，不许带着已知问题起子智能体。换入口不换遍数：从产物反推 / 从调用方反推 / 从失败路径反推 / 把新代码注释掉看哪些测试红。

**收敛阈值**：同一个问题最多修 2 轮，第 3 轮前停手，残留问题写进报告继续下一项。
噪声豁免不修：间距差 ≤ 4px、亚像素错位、装饰节点溢出、不在本次范围内的问题。

每次都是新的子智能体，**L3 最多两轮**（L3 轮数是唯一计数轴，L2 轮数不另算）。仍有 P0 就停下把没解决的列出来，问用户要不要第三轮。

## 八、预算、未决项与止损

到预算上限：已查完的项写全，其余逐项标「未查完（达到预算）」+ 原因，结论写「有条件通过」或「未查完」，不许写「通过」。

外部平台限制（403 / 配额 / 限流 / 控制台拦截）：记未决项，不重试、不计入轮次、不升级。

同一个修法失败两次：停下，写清卡在哪、试过什么、要用户定什么。不许静默换第三种变体接着试。

## 九、交付报告（结论 + 六节，缺一不可）

```
结论：通过 / 有条件通过 / 不通过
〇、需求对账（每条验收判据：做了 / 没做 / 部分做）
一、改了什么（文件 + 行号）
二、查了什么（六项逐条；自检几轮、终检做没做、用户是否确认）
三、验了什么（命令 + 输出，原样贴）
四、没验什么 + 未决项（不许空）
五、还剩什么风险
```

## 十、每轮收尾：总结 + 下一步

反思模式下，每一轮工作结束、进入空闲之前，必须给两块，各控制在几行：

```
总结：这一轮改了什么 / 验了什么（贴住那条命令）/ 没验什么
下一步：下一步具体做什么，或者需要用户定什么
```

三条硬规矩：

1. **不许省略**。哪怕只改了一行、只跑了一条命令，也要给这两块。
2. **不复述计划**。已经把计划说过的，不要在这儿重复一遍。
3. **不夸自己**。「已优化」「质量显著提升」这类句子一律不要，只写事实和命令输出。

**节流**：这两块是给用户的收尾，不是自证。同一轮里已经给过一次总结、后续只是补跑命令的，
直接给结论行即可（`验了什么 + 结果`），不必重贴两块。

## 十一、用户要「能粘给 DeepSeek 的规矩」

读 `templates/deepseek-开工令.md`，替四处：项目、技术栈、本次任务、不能动，整份原样输出，代码块包好。只要二轮那一段就用 `templates/二轮检测令.md`。

## 十二、复盘

三问：哪一处判断错了（定位到文件行号或产物位置）？六项里哪项本该拦住？补一条规则。落 `.workbuddy/复盘.md`，模板 `templates/复盘.md`。
