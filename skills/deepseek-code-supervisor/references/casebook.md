# 翻车档案

按症状查，不按项目查。每条都来自真实项目，不是假设。

用法：拿到一份代码或一个 bug，先扫这张表找同类症状，直接跳到"修法"，别从零推。

---

## A. 判断类：不是写错，是想错

### A-1 拿一份数据调到全中，当成通用能力

**症状**：第一份数据 17/17 = 100%，换一份 1/8 = 12.5%。

**根因**：规则是照着第一份数据逐条调出来的。证据就在代码注释里 ——
注释写着"否则 Q13 会被误判成词句赏析""『以《纸飞机》为题』不含『标题』二字"，连题号和原题文字都留在里面。

**修法**：分出调参数据和验证数据。验证数据要挑最像的负例。
报告写"第一份 X%，第二份 Y%"，不写"命中率 100%"。

**一句话**：能调到 100% 的规则，通常只对那一份 100%。

---

### A-2 把自己丢掉的数据，解释成"数据本来就没有"

**症状**：9 处出处只标出 2 组。解释是"那些板块底下没有题号，挂不上"。

**根因**：`if (byGroup.has(gid)) continue` —— 一个题组只留第一条。

**修法**：遇到"没输出/查不到/标不出来"，第一动作是去产物里数一遍，不是改提示词。

**一句话**：先证明数据不存在，再解释为什么没有。

---

### A-3 把"这个工具做不到"说成"这件事做不到"

**症状**：合卷遇图片直接中止，告诉用户"带图不能合"。

**根因**：工具的保守策略被当成能力边界。而另一条路径（编辑器搬块）带图一直是好的。

**修法**：问自己一句 —— 是这件事做不到，还是这个工具做不到？换路径先办事。

**一句话**：用户要的是结果，不是你这条路径的成功。

---

### A-4 把"碰巧生效"算成自己实现的

**症状**：底纹保留成功，报告里写成工具能力。

**根因**：没做"拿掉实现看还在不在"的验证。核对原件后发现分布完全一致 —— 是原件自带的。

**修法**：任何"这个效果是我们实现的"，先做一次移除验证。

**一句话**：没做过对照的效果，不算你的。

---

### A-5 需求理解反了方向

**症状**：用户说"统一中文标点"，实现成全部转半角。

**根因**：把"统一"理解成"全都转成同一种写法"，选了半角。中文标点 = 全角。

**修法**：涉及方向的词（全/半、加/减、左/右、前/后），动手前用一句话复述给用户确认。

**一句话**：方向错了，做得再细都是白做。

---

## B. 静默类：错误消失了，功能看起来只是"不太对"

### B-1 类型不对，整条被丢

```js
if (it.isQingdao !== true) continue;   // 模型回 "true"，整条丢
```

**表现**：明明是青岛题却不显示出处的，看起来像"模型能力不行"。
差点因此去调提示词、开思考模式 —— 全是白费功夫。

**修法**：宽读 + 三态（`true` / `false` / `null`），失败原因分开记。

**一句话**：类型不受控的外部输入，必须先归一化再判断。

---

### B-2 `null` 被当成 0

三连：`title: null` → 第 0 段是标题（首段被改坏）；`stars: null` → 1 星；`confidence: null` → 0 分被误拦。

**修法**：校验函数第一行挡 `null / undefined / ''`。

**一句话**：`Number(null) === 0` 是 JS 送给你的第一颗雷。

---

### B-3 状态机锁死

`inAnswer` 一遇 `【答案】` 永久置位，吞掉后面 165 段（`question 12→1`）。

**原因**：假设答案都在末尾集中，真实卷子是逐题就地给答案。

**修法**：状态改成"段落级 + 有限续行"，遇新题干立即打断。

**一句话**：凡是"一旦进入就出不来"的状态，都要写出退出条件。

---

### B-4 管道吃掉退出码

```bash
python x.py | tail -20 ; echo $?   # 拿到的是 tail 的
```

**修法**：重定向到文件再查 `$?`。

**一句话**：验退出码时，别让任何管道接在后面。

---

### B-5 非 0 退出码被当成"工具坏了"

脚本用非 0 表示"有硬伤/没找到/验收不通过"，AI 当成故障反复重跑，空转很久。

**修法**：每个非 0 分支打印"这是验收结论，不是脚本故障，不要重跑"。

**一句话**：让脚本自己说清"我这是结论还是故障"。

---

### B-6 空 catch / 裸 except

**表现**：功能不正常，日志干净。

**修法**：最差也要 `log.warn(e)` + 降级 + 报告里写一条。

**一句话**：吞掉的错误，最后都由用户来发现。

---

## C. 产物类：代码改了，东西没变

### C-1 产物是旧的

改完代码，`out/` 下还是上一版。用 Python 解 `document.xml` 才对出来新旧差异。

**修法**：交付前打开产物文件，数出那个数。

---

### C-2 打包报成功，文件不在

`Packaged 12 files to: ...zip` 打印了，测试也读到过，之后没有任何删除命令，文件却没了。

**修法**：产物存在性单独验（`ls -l` + md5），双份存放。

---

### C-3 只改了内存对象

测的是内存里的结构，序列化/落盘那段是坏的。

**修法**：断言要落在"读回来的产物"上，不是"写进去的对象"上。

---

## D. 范围类：改多了

### D-1 顺手扩展需求

用户要"把 logo 贴进去"，实现成"做了圆角徽章 + 边框 + 角饰"。
原话：「我没让你给 logo 生成徽章啊……我后续会自己调整（圆角/边框），不需要你。你只负责把 logo 贴进去。」

**修法**：交付前对照需求原文，逐条打勾。多做的部分单独列出来，让用户决定要不要。

**一句话**：多做的那部分，也是要用户花时间验收的。

---

### D-2 全量重写文件

用户要求：「其他布局格式一律不动，原本的格式就很好了，只需要调整我让你调整的这几部分」。

**修法**：改哪里贴哪里。整文件重写让 diff 变成一团，用户没法审。

---

### D-3 用更复杂的系统解一个"范围要更小"的问题

做了一整套"证据分级 + 置信度闸门 + 复核清单 + 人工确认界面"。
用户全部推翻：「不需要置信度之类的额外指标，不需要如此复杂的逻辑系统，越简单越好」。

**修法**：先问"这件事的范围能不能收窄"，再问"怎么判断得更准"。
范围外的东西，代码里干脆没有对应动作 —— 这比任何阈值都可靠。

**一句话**：他要的是少做几件事，不是把每件事判得更准。

---

## E. 一致类：四套说法

### E-1 两套规则并存

`renumber.py` 和 `verify_paper.py` 各存一份题号正则 → "dump 认得出、verify 认不出"。

**修法**：抽公共模块，只维护一处。

### E-2 文档说拦截，代码在迁移

SKILL 写"遇图自动拦截"，代码已改成"自动迁移"。4 处规则与实现打架。

**修法**：改完 grep 旧口径词，命中数写进交付说明。

### E-3 版本号跳版

`1.0.0 → 2.0.0`、`1.0.0 → 1.3.0`，被指出「版本号不能这么跳」。规则：每次改动只 +0.0.1。

**修法**：改完 `plugin.json` 必须重跑注册脚本，否则两处版本不一致。

## F. 测试类：绿得可疑

### F-1 空转断言

夹具没触发被测路径 → 切出 0 片 → 四条断言在空数组上跑，三条"越界被拦"假通过。

**修法**：夹具要能真的触发路径；断言前查前提，前提不成立标"跳过"并计数。

### F-2 恒真式

`nums == range(1,1)` 恒真 → 空卷也打印"✓ 题号连续"。

**修法**：空集合单独判，别让循环体一次没跑就报通过。

### F-3 桩写错，测试照过

桩只有 `text()`，健康检查走 `json()` → 抛错被吞 → 显示"AI 未就绪"，测试通过。
用例间不清缓存 → 第二组命中第一组，桩根本没调用。

**修法**：桩同时实现 `json()` / `text()`；每个用例前清缓存。

### F-4 jsdom 不加载 CSS，DOM 断言全绿

AI 助手面板展开后一片空白。jsdom 的 DOM 断言全过 —— 因为样式表根本没加载。

**修法**：样式/交互类改动必须肉眼看一次，或做"选择器命中法"断言。

```js
[...styleSheets[0].cssRules].filter(r => el.matches(r.selectorText))
```

把命中的规则连同各自的 `display` 全列出来，谁在抢一眼就明白。

### F-5 死样式撞名

旧版残留的 `.fold-body { display: none }` 没删，新面板又用了 `.fold-*`。
收起态正常，展开态被旧规则按死 → 内容区空白，箭头照转、`aria-expanded` 也是 true。

**修法**：删死样式前 grep 全工程零命中；展开态**显式**写 `display:block`，成对写规则。

## G. 这台机器的固定坑（Windows）

| 坑 | 症状 | 做法 |
|---|---|---|
| `git clone` 拉 GitHub | 一律失败（代理 502 / 直连超时） | 用 `codeload.github.com` 的 tarball |
| Edge `--headless --screenshot` | rc=0、输出全空、PNG 不落盘 | 走 CDP（`Page.captureScreenshot`） |
| `taskkill /IM msedge.exe` | 把用户正在用的浏览器一起杀 | 只杀自己 spawn 的那棵进程树 |
| WPS 打开着的文件 | `PermissionError`，`save_file` 假成功 | 先请用户关闭，保存后 stat + 读回校验 |
| 批量删除 >50 文件 | safe-delete 垫片拦死 | 构建产物加 `CODEBUDDY_SAFE_DELETE_ENABLED=0` |
| `tar` 用 `C:\` 路径 | `Cannot connect to C:` | 先 `cd /tmp` 用相对路径 |
| `scp` 端口 | `-p` 是保留时间戳 | 用 `-P` |
| Vite 只绑 IPv6 | `curl localhost` 200，浏览器白屏 | `--host 0.0.0.0`，`netstat` 确认 |
| `find -exec rm -rf` 在 MSYS | 静默失败，缓存还在 | 用确切路径 `rm -rf` |
| 中文两端对齐 | 题号后的空格被拉成大空档 | 去掉空格，直接 `1.《…》` |

## H. 发布类：一次就能出事

### H-1 黑名单式构建，把密钥发布出去

静态构建按黑名单排除根目录（列了 `backend/`、`node_modules/`）。
迁移期间新建的 `_deploy/`（API 密钥、JWT 密钥、SSH 私钥、15MB 数据库导出）和 `.workbuddy/`
不在名单里，被原样复制进 `dist/` 并上传。工作日志**真的在公网可下载了**。

**修法（按顺序）**：

1. 改白名单式：根目录下任何以 `.` 开头的条目一律不进产物。
2. 加构建后闸门：扫 `dist`，命中 `.pem/.key/.sqlite/.env/secrets/_deploy/` 隐藏条目就让**构建失败**并列出文件。
3. 部署清空目录别用 `www/*`（`*` 不匹配点开头条目），用 `rm -rf $DIR && mkdir -p $DIR`。
4. 上线前真的去请求这些路径验收。

### H-2 用状态码判断文件是否暴露

Cloudflare Pages 对不存在的路径返回 **200 + index.html**（SPA 兜底）。
看状态码会得出完全相反的结论。

**修法**：看 `Content-Type` 和内容。最稳的对照是再请求一个绝不可能存在的路径，两者表现一致即证明是兜底。

### H-3 本机路径、个人信息进发布包

包里搜出本机用户目录、学校名、真实姓名三样。

**修法**：发布前 grep 三样 —— 用户名、学校/公司名、真实姓名。命中数必须是 0。

**一句话**：发布包不是工作目录，它会被人打开看。
