# 取证清单 · 判据与真实案例

> 文件较长，**按小节跳读**（`## 取证 N`），不要整份读完。一次挑 2–3 条够用。

二轮检测的六项是主线：逻辑错误 / 死代码 / 原有功能 / 误用 bug / 功能失效 / 结构内容。

这份文件**不是第二套检查表**。它是取证方法——判某一项"过"的时候，拿什么证据支撑。
按改动性质挑 2–3 条用；全扫一遍会变成走流程。

| 你在判六项里的 | 用下面这几条取证 |
|---|---|
| 1 逻辑错误 | 2 可证伪、3 静默、6 边界；改补丁/迁移 → 8.1 幂等方向 |
| 2 死代码 | 2 可证伪（注释掉看测试红不红）；删功能 → 8.2 爆炸半径 |
| 3 原有功能 | 4 接口、5 一致 |
| 4 误用 bug | 0 回滚点、6 边界 |
| 5 功能失效 | 1 产物、2 可证伪 |
| 6 结构内容 | 5 一致；写文件 → 8.3 落盘复检；做预算表 → 8.4 单位 |
| 规则/正则/阈值类改动 | 7 泛化 |
| 只有用户看得见的现象 | 8.5 外部观测 |

下面每条给：判据、怎么验、真实翻过车的案例。

## 取证 0 · 回滚点（前置）

动手前先能退回去。

```bash
# 有 git
git add -A && git commit -m "before: <这次要改什么>"
# 没 git
cp -r <目录> <目录>.bak-$(date +%Y%m%d-%H%M)
# 只改几个文件
md5sum <文件...> > .before.md5
```

交付时贴"改动前后对照"：没动的文件 md5 必须完全一致。

> 真实做法：三份原卷施工前后 md5 完全一致，才敢说"没动别人的东西"。
> 这条不是形式主义 —— 用户最先问的往往是"你有没有碰我别的文件"。

## 取证 1 · 产物

**判据：换掉实现，产物必须变。产物不变 = 代码没生效。**

### 怎么验

| 产物类型 | 验法 |
|---|---|
| 文件（docx/xlsx/zip/pdf） | 改前改后各留一份，比对 md5 + 抽出关键内容比对 |
| 网页 | 截图；或直接读 DOM 文本 / `curl` 拿 HTML 里的关键片段 |
| 接口 | `curl` 真实请求，贴响应体关键字段，别用 mock |
| 数据库 | 直接 `select` 出来数行数 |
| 命令行工具 | 跑真实输入，贴 stdout 关键行 + 退出码 |

### 三种假象

1. **产物是旧的** —— 代码改了但没重跑，或者跑的是另一条命令。
2. **只改了内存对象** —— 序列化/落盘那一步是坏的，测试看不出来。
3. **缓存命中** —— 第二次跑的是第一次的结果。

### 真实案例

**案例 1-A｜产物没换，代码白改**

改完标记顺序后，`out/` 下的 docx 还是上一轮的旧版。
用 Python 解 `word/document.xml` 才对出来：旧版第 8 段是 `★ 1．小语将…`，新版应该是 `1．【2026·青岛中考】★ 小语将…`。

> 教训：交付前必须打开产物文件本身，不能只看代码里"写回逻辑已经改了"。

**案例 1-B｜"标不出来"被解释成"设计如此"**

答案区实际有 9 处 `【来源】`（段 42/60/65/75/88/128/186/237/263），工具只标出 2 组。
当时的解释是"G3–G8 那些板块底下没有带数字题号的题，所以挂不上出处 —— 是正确的"。

**这个解释是错的。** 真因是一行去重：

```js
if (byGroup.has(gid)) continue;   // 一个题组只留第一条出处
```

`一、积累运用` 这一个题组下挂了 19 道题、来自 8 份不同卷子，前 7 条全被丢掉。

> 教训：遇到"标不出来/查不到/没输出"，第一动作是**去产物里数一遍**（`【来源】` 到底几处、在第几段），
> 不是顺着"看不见"去改提示词。那次提示词根本没毛病。

**案例 1-C｜打包报成功，文件不在**

`package_expert.py` 明确打印 `Packaged 12 files to: C:\...\xxx.zip`，端到端测试也确实读到了它（md5 校验通过），
之后没有任何删除命令，文件却不见了。

> 教训：产物的"存在性"要单独验一次（`ls -l` + md5），别只信命令的成功输出。

## 取证 2 · 可证伪

**判据：把期望值改坏一个字节，测试必须红。还绿 = 哑弹。**

### 怎么验

```bash
# 1. 先跑一遍，确认绿
python verify.py; echo "exit=$?"

# 2. 故意把期望值改坏
sed -i 's/"expect": 120/"expect": 121/' plan.json
python verify.py; echo "exit=$?"     # 必须非 0

# 3. 恢复，再跑一遍确认绿
```

改期望值、改输入、或者把被测函数直接 `return` 掉，三种任选。

### 三种哑弹来源

| 来源 | 表现 |
|---|---|
| **空转** | 夹具没触发被测路径，断言在空数组上跑，恒真 |
| **恒真式** | `range(1,1)` 是空 → 循环体一次没跑 → 打印"✓ 通过"；`all([])` 是 `True` |
| **桩没被调用** | 用例之间没清缓存，第二组命中第一组结果，网络桩根本没跑 |

### 真实案例

**案例 2-A｜四条断言全空转，三条还"假通过"**

测试默认夹具 `raw-24.docx` 的答案区没有出处线索，被 `SOURCE_HINT` 预筛掉 → 切出 **0 片** → 出处任务一次请求都不发。
于是四条出处断言全部空转，其中三条"越界被拦掉"因为**列表本来就是空的**而假通过。

修法（缺一不可）：

1. 夹具换成 `raw-08.docx`（答案区有出处，切出 9 片）。
2. 加 `skip()`：`answerChunks === 0` 就明确标"⊘ 跳过"，并计入"跳过 N"，不许默默算通过。

**案例 2-B｜空卷也报"通过"**

```python
if nums == range(1, 1):      # 恒真：range(1,1) 是空的
    print("✓ 题号 1-0 连续")
```

改成：空序列直接警告 + 退出码 1。

**案例 2-C｜桩写错，测试静默显示"未就绪"**

桩只提供了 `text()`，但健康检查走的是 `res.json()` → 抛错被吞 → 界面显示"AI 未就绪"，测试照常"通过"。
另外用例之间没 `clearCache()`，第二组命中第一组缓存，桩根本没被调用 → 假通过。

> 教训：一个桩要同时实现 `json()` 和 `text()`；每个用例前必须清缓存。

## 取证 3 · 静默失败

**判据：每条失败路径都要有声音。**

### 怎么验

```bash
python skills/deepseek-code-supervisor/scripts/scan_risks.py <项目目录>
```

再人工过一遍这四类：

| 形态 | 为什么危险 |
|---|---|
| `catch {}` / `except: pass` | 错误消失，表现为"功能不正常" |
| `Number(null) === 0` / `int(null)` | 判不出被读成 0，改坏第一条数据 |
| `if (x !== true) continue` | 类型不对就整条丢，看起来像"模型能力不行" |
| `cmd \| tail` / `2>/dev/null` | 退出码或错误被吃掉，故障看起来像成功 |

### 真实案例

**案例 3-A｜"模型判不出来"其实是代码把结果扔了**

```js
if (it.isQingdao !== true) continue;
```

模型回 JSON 时 `isQingdao` 类型不受控：可能是 `true` / `"true"` / `1` / `"是"` / `"青岛"`。
字符串 `"true"` ≠ 布尔 `true` → 整条静默跳过 → 表现成"明明是青岛题却不显示出处"。

差点因此去调提示词、开思考模式 —— **全是白费功夫**。

```js
const isTrue = (v) =>
  v === true || v === 1 || /^(true|yes|y|是|对|青岛)$/i.test(String(v ?? '').trim());
```

配套：`null`（判不出）和 `false`（明确别处）的失败原因要**分开记**，否则没法诊断。

**案例 3-B｜`null` 被当成 0，三连**

三处都**不改代码就发现不了**，而且都会改坏数据：

| 字段 | 本意 | 被读成 | 后果 |
|---|---|---|---|
| `"title": null` | 没有标题 | 第 0 段是标题 | 首段被改坏 |
| `"stars": null` | 判不出 | 1 星（clamp 后） | 难度表整体拉平 |
| `"confidence": null` | 没表态 | 0 | 判定被误拦 |

修法：校验函数第一行就挡 `null / undefined / ''`。

**案例 3-C｜状态机锁死，吞掉 165 段**

`inAnswer` 一遇 `【答案】` 就永久置位。真实卷子是**逐题就地给答案**（`1．题干 → 【答案】 → 下一题`），
第一个 `【答案】` 在第 17 段，之后全被吞：`answer 32→165`、`question 12→1`、`instruction 11→0`。

修法：改成"段落级 + 有限续行"，遇题干立即打断。

**案例 3-D｜管道吃掉退出码**

```bash
python compose_paper.py | tail -20 ; echo $?    # 拿到的是 tail 的退出码
```

差点误判"安全拦截没生效"。

修法：要验退出码就重定向到文件再查 `$?`。

**案例 3-E｜非 0 退出码被当成"工具坏了"**

脚本用非 0 表示"有情况"（有硬伤、没找到文件、验收不通过），AI 当成故障反复重跑，空转很久。

修法：每个非 0 分支都打印一句"这是验收结论，不是脚本故障，不要重跑本命令"。

## 取证 4 · 接口对齐

**判据：两端字段名、类型、可空、单位先对齐，`null` 和空数组各跑一次。**

### 必查五项

| 项 | 典型事故 |
|---|---|
| **字段名** | 前端取 `data.items`，后端返 `{list: []}` → 静默空数组 |
| **类型** | ID 字符串 vs 数字；`"1" == 1` 在弱类型里为真，掩盖问题 |
| **可空** | `null` / `undefined` / `""` / `0` 四种输入各跑一次 |
| **单位** | px / cm / twip / EMU；时间戳秒 vs 毫秒；比例 `1` vs `100%` |
| **顺序** | 有序容器的子元素顺序错了，解析器可能直接报"文件损坏" |

### 真实案例

**案例 4-A｜单位算错，全变 0**

`w:pgSz` / `w:pgMar` 单位是 **twip**（1cm ≈ 566.93），按 EMU 算 → 全部算成 0。
`w:firstLineChars="200"`（中文字符数）比 EMU 值可靠。

**案例 4-B｜JSON 里多写一个反斜杠，路径被二次转义**

`--json-file` 里路径写 `\\\\`（JSON 里两个反斜杠），解析后再转一次 → 回显成 `C:////Users////...`。
文件能落盘，但正确写法是 JSON 里只写 `\\`（解析后一个反斜杠）。

**案例 4-C｜缓存键漏了一半，媒体被复制两份**

```python
# 错：只按 alias 缓存
cache[alias] = new_rid
# 对：按 (alias, old_rid) 缓存
cache[(alias, old_rid)] = new_rid
```

同一段内容搬两次 → 媒体复制两份，rId 指向不同。

**案例 4-D｜外部状态不在你控制里**

`settings.json` 被应用侧同步清掉（一天出现两次），打包脚本报"Team 必须提供 settings.json"，
而目录里确实没有。

修法：打包前用 `printf` 补回，和打包命令串在同一条 shell 里，避免中间被清理。

## 取证 5 · 口径一致

**判据：改完规则，全文 grep 旧口径的词，命中数必须是 0，并把命中数写进交付说明。**

### 怎么验

```bash
grep -rn "自动拦截\|暂不支持\|硬搬会丢图\|不自动迁移" --include="*.md" --include="*.py" .
```

命中 0 才叫同步完成。命中非 0 就在交付说明里逐条解释。

### 四处必须同口径

1. `SKILL.md` / README
2. 代码注释
3. 配置与常量
4. 实现本身

### 真实案例

**案例 5-A｜文档说"拦截"，代码在"迁移"**

SKILL 写"遇图自动拦截"，代码早已改成"自动迁移图片引用"。
结果：4 处规则与实现打架（SKILL 两条互斥路径表 / 退出码表 / 禁止循环第 4 条 / 能力边界），
靠全文 grep 才对齐。

> 这条的起因是用户一句质问："合卷拦下以后呢？有图片就不做了？你之前带图做的时候也不出错啊"
> —— 把一个能解决的问题标成"不可做"，还逼着用户绕路，**这是设计缺陷，不是保护**。

**案例 5-B｜两份代码各存一套规则，必然漂移**

`renumber.py` 和 `verify_paper.py` 各有一份题号识别正则 →
会出现"dump 认得出、verify 认不出"。

修法：抽成 `paperfmt.py`，只维护一处。

**案例 5-C｜两个版本的数据基准不一致**

Python 版 `ai_annotations.json` 还是 5 星制（2/3/3/3/3/4/4/5），
JS 版 `config.js` 已经是 1–3 星制 → 用户跑哪个版本得到两套星级。

**案例 5-D｜文档数字按摘要写，没核对**

手册写"清除加粗 1204 处 / 切出 3612 个 run / 全套 3.1s"，
复跑实测是 **4 / 2359 / 3.7s**。

> 这是用户最在意的红线：**数字必须能从产物里数出来**。按摘要写数字等于编数据。

## 取证 6 · 边界

**判据：空、单条、多条、超长、重名、并发，六个各跑一次。**

### 最容易漏的是"1 条"

代码通常按 `0 / 1 / ≥2` 分三支。测的时候只测首尾，中间那支永远没人跑。

### 真实案例

**案例 6-A｜"1 条"分支插错位置**

出处挂载分三支：`0 条不挂 / 1 条挂题目语 / ≥2 条挂题号后`。
只测了 `≥2`，`1 条` 那支把 `【出处】` 插到了题号后面，而不是题目语前面。

**案例 6-B｜去重键选错维度，一个题组挂 8 份卷子**

`gid`（题组）去重 → 一个题组下 19 道题来自 8 份卷子，前 7 条出处全丢。
改成 `gid + 出处签名` 后，2 组 → 8 组。

**案例 6-C｜子元素顺序错，Word 报"文档已损坏"**

`tblPr` 子元素有固定序列（`jc` 在 `tblW` 之后、`tblCellSpacing` 之前），
且 `tblPr` 必须是 `w:tbl` 的第一个子元素。插错 → Word 打不开，**node 侧测试全绿看不出来**。

**案例 6-D｜通配符跨目录匹配，响应头重复**

`_headers` 里的 `/*.js` 不是单层通配，`/hanzi/js/app.js` 会被 `/*.js` 和 `/hanzi/js/*` 同时命中 →
响应头变成 `public, max-age=300, public, max-age=300`。值相同时无害，值不同就是隐式冲突。

**案例 6-E｜圈码字符表只到 ⑳**

`classifier.js` 的 `CIRCLED` 常量漏了 ㉑–㉚ → 8 段原文判成 unknown，字体/缩进全错。
纯编码遗漏，一行可修，但只有换一份数据才暴露。

## 取证 7 · 泛化

**判据：规则类改动，必须在没参与调参的第二份数据上跑一遍。**

### 怎么验

1. 明确分出"调参数据"和"验证数据"。
2. 验证数据要挑**最像的负例**（最能暴露过拟合的那种），不能挑顺手的。
3. 报告必须写成："第一份 X%，第二份 Y%"，不许只写 X%。

差距超过 30 个百分点 → 判定过拟合，返工。

### 真实案例

**案例 7-A｜17/17 → 1/8**

第一份卷子星级识别 17/17 = 100%，对外说"规则泛化能力强"。
换一份没参与调参的卷子：**1/8 = 12.5%**。

真相：拿那 17 道题把规则调到了全中。证据留在代码注释里 ——
`config.js` 的 `POINT_RULES` 注释直接写着"否则 Q13 会被误判成词句赏析""『以《纸飞机》为题』不含『标题』二字"，
连题号和原题文字都留在了注释里。

> 交付规则型工具时，必须主动说明"规则是在什么数据上调出来的"。
> 说"规则泛化能力强"是夸大，说"在第一份上调到 100%"才是事实。

**案例 7-B｜四处失效原因，全部有证据**

第二份卷子上 12 段未命中（16.2%），四个原因：

1. 圈码表只到 ⑳（编码遗漏，一行可修）
2. 题干被拆成两段：题号行只有 `4．【导演说剧】`，真题干在下一段 → 星级读不到，真题干还被误判成引文
3. 考点正则词表太窄（"简析…高妙""最想说的话"都不在枚举内）—— 这条路没有尽头
4. 答案区标记不同：本卷用 `【答案】`，规则只认 `《…》参考答案`，`inAnswer` 从未开启

**案例 7-C｜别把"碰巧"算成成绩**

底纹 F2F2F2 看起来"保留成功"，核对原件后发现分布完全一致（NO_SHD 3→1、auto 70、F2F2F2 2），
证明是**原件自带**，不是工具做到的。

> 报告里凡是"这个效果是我们实现的"，都要先做一次"拿掉实现看还在不在"的验证。

## 取证 8 · 四条按改动类型触发的专项（SKILL.md 六项指向这里）

不是每次都要全做。**改了哪类东西，才做哪条**，每条都有具体的"怎么验"。

### 8.1 幂等方向（改补丁 / 迁移 / 同步逻辑时）

**判据：判断"改过没有"，只能看「新文已在」，不能看「旧文不在」。**

方向搞反是补丁类事故的头号来源：第二次跑会把已经打过补丁的文件再改一遍。
"旧文不在"有两种可能——**真的改过了**，或者**这文件本来就没有旧文**。两者长得一模一样。

怎么验：

1. 每处改动留一个**只出现在新版里的 marker**（一行注释、一个新字段、一个版本号）。
2. 判据写成 `has(marker)`；`!has(oldText)` 一律不算判据。
3. 整节替换用**成对 marker**（起点 + 终点），不要用边界锚点——边界会漂。
4. 校验用精确计数（`count == 3`），不许用 `>= 0`——`>= 0` 永真，等于没校验。

**自测动作**：对同一份文件**连跑两遍**，第二遍必须报"已是最新、跳过"，且文件 md5 不变。

### 8.2 删除功能的爆炸半径（删模块 / 删字段 / 删分支时）

**判据：先摘调用点，后删实现。顺序反了会留下悬空引用，静态检查未必抓得到。**

怎么验（按顺序做，别跳）：

1. **侦察**：每个待删关键词在核心文件里出现几次？数量决定是"精确摘除"还是"整块重写"。
2. **列全集**：调用点清单 + 被谁 import（决定爆炸半径）。
3. **摘调用点**，再删实现。
4. 删完 grep 一遍残留关键词，必须是 0 处。

### 8.3 落盘后重读复检（凡是写文件的改动）

**判据：`写成功 ≠ 写对了`。**

`writeFileSync` 不抛异常，只说明系统接受了调用，不说明字节到位、编码正确、内容完整。

怎么验：写完**用独立路径重读**一遍——不是读内存里的那个字符串，是重新打开文件读：

```bash
# 写完立刻核对
python -c "print(open('out.txt', encoding='utf-8').read()[:80])"
# 或直接比字节数
wc -c out.txt
```

三种常见"写成功但没写对"：编码静默替换（中文变问号）、被同名旧文件覆盖失败、
追加模式写成覆盖模式（旧内容没了）。

### 8.4 数字口径与单位（拿大小 / 计数做预算表时）

**判据：字符数、字节数、token 数是三个不同的数，混用会让预算表整体偏低。**

| 拿到的 | 实际含义 | 换算 |
|---|---|---|
| `readFileSync(p,'utf8').length` | **字符数**（UTF-16 码元） | 中文 1 字 = 3 字节 |
| `statSync(p).size` | **字节数**（UTF-8） | 唯一的真实大小 |
| `Buffer.byteLength(s,'utf8')` | **字节数** | 同上 |

- 凡是包体、配额、上限、上传体积，**一律用字节数**，并在表头标单位。
- 中文文档按字符数算预算，会比真实大小**低约三分之二**，而且肉眼看不出来。
- 实测数字没回传之前，报告里不写估值。

### 8.5 外部观测（只有用户能看见的现象）

有些故障**进程自己看不见**：GUI 黑框、错位、卡顿、只在真机上出现的白屏。
进程内查询拿到的永远是"我很正常"。

**判据：这类问题必须有进程外的证据，否则写「未验」。**

- 窗口类：从外部枚举窗口做差分，不要问进程自己有没有弹窗。
- 界面类：截图 / 真机录屏，不用"代码里已经设置过了"当证据。
- 跨进程状态：启动、观察、关闭**在同一次调用里完成**——分两次做会读到上一轮的残留。

> 对应元原则 5：**进程的自述不可信，外部观测才算证据。**
